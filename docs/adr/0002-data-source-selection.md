# 0002. Data source selection for the Extract stage

## Status
Accepted

## Context
This repository is a portfolio piece intended to demonstrate ETL engineering
skills (CSV/Excel/JSON processing) for freelance work. We need a public data
source that:

- requires no authentication or API key (so anyone cloning the repo can run it
  immediately);
- is stable and well documented;
- represents a realistic, commercially relevant domain (retail / e-commerce),
  since retail analytics is a common freelance request;
- returns a reasonably rich schema (nested objects, arrays, mixed types) so the
  Transform stage has real normalization work to do.

Options considered:

| Option | Domain | Auth | Notes |
|---|---|---|---|
| [DummyJSON](https://dummyjson.com/docs/products) `/products` | Retail / e-commerce catalog | None | ~194 products, rich nested schema (dimensions, reviews, meta), paginated REST API |
| [Fake Store API](https://fakestoreapi.com) | Retail catalog | None | Simpler/flatter schema, fewer fields, smaller catalog |
| [datos.gov.co](https://www.datos.gov.co) (Socrata) | Colombian open data | None (rate-limited without app token) | Real-world data, but heavier setup and inconsistent schemas across datasets |

## Decision
Use the **DummyJSON Products API** (`https://dummyjson.com/products`) as the
data source for the Extract stage.

It offers a realistic retail/e-commerce schema (pricing, stock, categories,
ratings, nested reviews, shipping/warranty metadata) with no authentication,
native pagination (`limit`/`skip`), and a stable, documented contract — making
it a good balance of realism and reproducibility for a public portfolio
project.

## Consequences
- The dataset is synthetic: `reviews[].reviewerEmail` and similar fields are
  fake data generated by DummyJSON, not real personal information. No PII
  handling is required, but the data dictionary documents this explicitly.
- DummyJSON regenerates/rotates its underlying data periodically (observed
  `meta.updatedAt` timestamps in the future relative to extraction date),
  meaning **repeated extractions are point-in-time snapshots, not an
  append-only historical record**. The pipeline treats each run's raw file as
  an independent snapshot (see [0003](0003-raw-data-storage-format.md)).
- If DummyJSON becomes unavailable or changes its schema significantly, the
  Extract module (`src/extract/extract_dummyjson.py`) is isolated behind a
  single-responsibility script and `config/config.yaml`, so swapping the
  source requires changes in one place.
